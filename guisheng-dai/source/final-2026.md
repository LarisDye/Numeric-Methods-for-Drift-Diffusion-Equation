两人一组，自由组队。围绕一个数据科学计算问题完成项目，满分为 100 分。

## 项目要求

自行选择题目，可以实现已有算法、改进现有实现，或提出新的方法；不要求算法创新，但应有明确的计算问题和本人完成的实质性工作。

- 说明要解决的问题、所用模型或算法，以及主要计算开销在哪里。
- 根据问题选择本课程涉及的技术，例如 Rcpp、Armadillo、Eigen、并行计算、NumPy、PyTorch 或 CUDA。不要求覆盖全部模块，也不要求同时使用 R 和 Python。
- 与合理的基准方法比较，分析时间、内存、数值精度或任务效果，并解释方法的适用范围和局限。
- 可以从课件、作业或开源项目出发，但须说明复用了什么、增加了什么。不能仅更换数据、调整参数、运行现有示例或调用现成模型接口作为全部工作。

## 选题方向

以下仅供参考，也可以选择其他符合要求的计算问题。

| 方向 | 项目例子 |
|----------------|----------------------------------------------------------------|
| 统计与数值计算 | 统计模型的高效实现；稠密、稀疏或近似求解方法的比较 |
| 并行计算 | Monte Carlo、Bootstrap 或模拟研究的串行与并行实现，分析任务规模和并行开销 |
| 深度学习与 AI | 实现并验证神经网络或强化学习算法，研究批量计算、训练或推理效率 |

## 实验与验证

- 用小规模测试、参考实现或已知性质验证正确性，说明误差标准。记录随机种子，随机算法通过多次独立运行报告结果的波动。
- 选择合理基准，在可比的输入、精度或任务效果下比较，分析不同规模或设置下的表现；近似算法同时报告误差与计算成本。
- 报告硬件、软件版本、数据规模、并行度和计时范围。性能计时先预热、再重复测量，保留原始记录并汇总；使用 GPU 时处理异步执行，核心计算计时不含编译、绘图和结果验证。

不要求改进版本一定更快，也不按加速倍数或硬件性能直接评分。未获得预期提升时，应有正确实现、充分实验和原因分析。

## 代码与复现

提供结构清晰、可安装或运行的项目，不要求上传 CRAN 或 PyPI。

- 为项目创建公开的 GitHub 仓库，使用 Git 管理并保留开发历史。如因数据隐私等原因需要使用私有仓库，须在 `README.md` 中说明理由，并向教师或助教开放访问。不得将隐私数据上传至公开仓库。
- 在 `README.md` 中写明成员及分工、依赖与版本、安装或编译命令、测试及实验运行命令，并提供一个可运行的小规模示例。
- 注明使用的外部代码、数据和参考资料，区分本人实现与复用部分，并遵守相应许可。
- 可以使用 AI 工具。声明覆盖整个项目，在 `README.md` 中说明工具、主要用途及验证方式；未使用也请明确说明。两位成员均须能够解释提交的核心代码和实验结果。

## 展示与评分

课堂展示于教学周第十二周随堂进行。每组 15 分钟，其中报告 10–12 分钟，其余时间提问交流。

| 评分项目 | 分值 | 主要考察内容 |
|-------------------------|--------------:|------------------------------------------------------------|
| 问题与方法 | 20 | 问题明确、范围适当，方法选择及计算瓶颈分析合理 |
| 实现与正确性 | 30 | 核心实现可靠，验证充分，能够说明本人完成的工作 |
| 实验与分析 | 25 | 基准和比较条件合理，记录完整，结论有实验依据 |
| 工程与复现 | 15 | 代码组织、Git 使用、依赖说明及运行入口清晰 |
| 报告与展示 | 10 | 表达准确简洁，能够解释代码、结果及局限 |
| 合计 | 100 | |

报告不超过 8 页，包含问题背景、模型与算法、实现与优化、实验设置、主要结果、局限及参考资料；不需要重复粘贴全部源代码。

## 提交要求

- 将最终版本推送至 GitHub，在 `README.md` 中提供仓库链接及最终提交的 commit ID；压缩包中的代码应与该版本一致。
- 提交完整源代码、`README.md`、复现主要图表所需的配置与脚本、必要的数据、主要实验记录，以及 `report.pdf` 和展示用的 `slides.pdf`。
- 数据过大或不能分发时，提供合法的获取方式及预处理步骤；如需训练后的模型，提供模型文件或下载方式。报告中注明完整实验的预计耗时和硬件需求。
- 不提交无关的大型数据、编译产物、缓存、密码、访问令牌、私钥或个人隐私数据。
